The diskless metadata coordinator, from first principles

Diskless topics keep Kafka data in object storage instead of on broker disks. Something still has to put that data in order, remember where every batch lives, and decide when an object in storage can be deleted. This guide builds that component, the diskless metadata coordinator, one idea at a time. Every idea starts with the problem that prompted it, and most come with a demo you can play with.

How to read this guide

The chapters form a chain. Each one solves a problem and, in doing so, uncovers the next one. Every chapter opens with a purple Why this exists box. It says what prompted the idea: a sentence in a Kafka Improvement Proposal (KIP-1150, KIP-1163, or KIP-1164), a failure the design must survive, or one of the two bars every decision has to pass. Each chapter closes with a green Takeaway and an orange What this leaves open box that leads into the next chapter. The boxes marked Try it are interactive. Click around in them: nothing you do can break anything.

You don't need to know the earlier versions of this design. Where an obvious idea fails, the guide shows the obvious idea first and then why the design does something else. Part 6 collects the earlier versions and every other rejected idea in one place.
